# Android Google Play Store Release Guide: LyricWave (TWA)

This guide documents the exact process to build, sign, and upload **LyricWave** to the **Google Play Store** using Google's official **Trusted Web Activity (TWA)** toolchain: **Bubblewrap**.

---

## 1. Prerequisites on the Build Machine

Building Android App Bundles (`.aab`) with Bubblewrap requires:
1. **Node.js**: v18+ (currently running v22)
2. **Java Development Kit (JDK)**: JDK 17 or JDK 21
   - Windows: Install via `winget install Microsoft.OpenJDK.17` or Oracle JDK.
   - Set `JAVA_HOME` environment variable to your JDK path (e.g. `C:\Program Files\Microsoft\jdk-17...`).
3. **Android SDK Command-Line Tools**:
   - Automatically downloaded by Bubblewrap on first run, or available through Android Studio.

---

## 2. Generating the Upload Signing Keystore (Once)

The upload key signs your Android App Bundle (`.aab`) before sending it to Google.

Run this command in a terminal outside the Git repository or in your secure directory:
```bash
keytool -genkey -v -keystore android.keystore -alias android -keyalg RSA -keysize 2048 -validity 10000
```
> [!CAUTION]
> **Backup your `android.keystore` file securely!**
> Never commit `android.keystore` to git. Save the keystore file and its password in your password manager.

To view your upload certificate SHA-256 fingerprint:
```bash
keytool -list -v -keystore android.keystore -alias android
```
Look for `Certificate fingerprints:` -> `SHA256: XX:XX:...`.

---

## 3. Building the Release Android App Bundle (.aab)

LyricWave includes a pre-configured `twa-manifest.json`.

To generate or update the native Android project and build the release bundle:

```bash
# 1. Initialize or validate the Bubblewrap project
cmd.exe /c "npx @bubblewrap/cli init --manifest=https://lyricwave.pages.dev/manifest.webmanifest"

# 2. Build the signed production Android App Bundle (.aab)
cmd.exe /c "npx @bubblewrap/cli build"
```

The output file will be:
`app-release-bundle.aab`

## 4. Digital Asset Links (Removing the Browser URL Bar)

For Android Chrome to verify that your app owns `https://lyricwave.pages.dev` and hide the top URL bar:

1. Upload your first `.aab` to **Google Play Console** (Internal testing track).
2. In Google Play Console, go to **Setup → App signing**.
3. Copy the **App signing key certificate SHA-256 fingerprint** (generated by Google Play App Signing).
4. Update [`public/.well-known/assetlinks.json`](file:///c:/Users/User/Documents/antigravity/serene-newton/.well-known/assetlinks.json) on line 7 with this fingerprint:
   ```json
   [
     {
       "relation": ["delegate_permission/common.handle_all_urls"],
       "target": {
         "namespace": "android_app",
         "package_name": "app.lyricwave.twa",
         "sha256_cert_fingerprints": [
           "YOUR_PLAY_APP_SIGNING_SHA256_FINGERPRINT",
           "YOUR_LOCAL_UPLOAD_KEYSTORE_SHA256_FINGERPRINT"
         ]
       }
     }
   ]
   ```
5. Deploy to Cloudflare Pages (`npm run deploy`).
6. Verify live with Google's Digital Asset Links API:
   `https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://lyricwave.pages.dev&relation=delegate_permission/common.handle_all_urls`

## 5. Google Play Console Listing Checklist

When setting up your app in the Google Play Console:
- **App Name**: LyricWave — Synced Lyrics Companion
- **Package Name**: `app.lyricwave.twa`
- **Category**: Music & Audio / Entertainment
- **Privacy Policy URL**: `https://lyricwave.pages.dev/privacy.html`
- **Data Safety Form**: See `docs/play-listing.md`
- **Content Rating**: Complete the IARC questionnaire (Music/Audio app without user-generated chat).
- **Target Audience**: 13+ (or General Audience).
- **Permissions Declaration**:
  - `RECORD_AUDIO`: Core feature is transient acoustic song recognition via microphone.
